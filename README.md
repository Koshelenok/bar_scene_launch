# bar_scene_launch

Запуск многопользовательской 3D-сцены бара одной командой.

Репозиторий не содержит кода приложения — это **лаунчер**: скрипт `start-bar-scene.sh` подтягивает клиент и сервер, собирает их в Docker-образы и поднимает всё локально. В браузере открывается трёхмерный бар, по которому ходят персонажи разных людей, а голос собеседников слышен тем громче, чем ближе их персонажи.

- клиент: [Koshelenok/bar_scene_client](https://github.com/Koshelenok/bar_scene_client) — React + TypeScript + Three.js
- сервер: [Koshelenok/bar_scene_ws_server](https://github.com/Koshelenok/bar_scene_ws_server) — ASP.NET Core + SignalR

## Быстрый старт

Нужен только [Docker](https://docs.docker.com/get-docker/) с плагином `docker compose`.

```bash
git clone https://github.com/Koshelenok/bar_scene_launch.git
cd bar_scene_launch
./start-bar-scene.sh
```

Откройте <http://localhost:8080/>. Чтобы позвать кого-то в свою комнату, скопируйте адрес из строки браузера — в нём уже есть `?room=<uuid>`.

Если каталоги `bar_scene_client/` и `bar_scene_ws_server/` отсутствуют, скрипт склонирует их сам. Первый запуск занимает несколько минут (скачиваются зависимости и собираются образы), последующие — заметно быстрее.

## Команды

| Команда | Что делает |
| --- | --- |
| `./start-bar-scene.sh` | Собрать образы и запустить контейнеры (то же, что `up`) |
| `./start-bar-scene.sh logs` | Показывать логи контейнеров |
| `./start-bar-scene.sh restart` | Перезапустить |
| `./start-bar-scene.sh down` | Остановить и удалить контейнеры |
| `./start-bar-scene.sh help` | Показать справку |

## Настройки

Всё задаётся переменными окружения перед запуском:

```bash
WEB_PORT=8090 ./start-bar-scene.sh          # порт, на котором открывается сцена
DOCKER_SUBNET=172.31.0.0/24 ./start-bar-scene.sh
CLIENT_REPO=https://github.com/... ./start-bar-scene.sh
SERVER_REPO=https://github.com/... ./start-bar-scene.sh
```

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `WEB_PORT` | `8080` | Порт хоста, на котором доступен клиент |
| `DOCKER_SUBNET` | `172.30.0.0/24` | Подсеть Docker-сети |
| `CLIENT_REPO` | репозиторий `bar_scene_client` | Откуда клонировать клиент |
| `SERVER_REPO` | репозиторий `bar_scene_ws_server` | Откуда клонировать сервер |

## Что делает приложение

Картинка и звук — в браузере, сервер только сводит участников.

- **3D-сцена бара** на Three.js: мебель, стены, лампы, тени. Модель лежит в `public/scene_to_glb_16.glb`.
- **Перемещение кликом**: клик по полу задаёт точку, персонаж идёт к ней и обходит препятствия.
- **Совместное присутствие**: персонажи других участников двигаются в реальном времени, у каждого свой постоянный цвет.
- **Комнаты**: изоляция по `?room=<uuid>` в адресе. Если параметра нет, UUID создаётся и записывается в URL — ссылку можно просто переслать.
- **Возврат на место**: позиция участника в комнате хранится в IndexedDB и восстанавливается после перезагрузки; записи старше часа удаляются.
- **Голосовой чат** по WebRTC: звук идёт напрямую между браузерами, сервер используется только для обмена сигналами. Громкость падает с расстоянием между персонажами.
- **Уборка призраков**: каждый клиент периодически опрашивает комнату, пропавшие участники убираются из сцены.

## Как это устроено

```
браузер ──HTTP──► Caddy (web, :80) ──► статика React-сборки
   │
   └──WebSocket──► Caddy /chatHub ──► ASP.NET Core SignalR (server, :5201)
                                              │
                                     рассылка всем клиентам
```

- `web` — контейнер с Caddy. Раздаёт собранный React-клиент и проксирует запросы `/chatHub*` в `server`.
- `server` — ASP.NET Core с SignalR-хабом `/chatHub`. Это простой ретранслятор: принимает `SendMessage(user, message)` и рассылает `ReceiveMessage` всем подключённым клиентам. Состояния не хранит.
- Клиенты передают через хаб JSON-сообщения: координаты персонажа, presence-опросы и WebRTC-сигналы. Разделение на комнаты происходит на клиенте фильтрацией по полю `room`.

## Разработка без Docker

Каталоги приложений можно клонировать вручную и запускать как обычные проекты — клиент на `http://localhost:3000`, сервер на `http://localhost:5201`:

```bash
cd bar_scene_client
npm install
npm start          # REACT_APP_HUB_URL по умолчанию ws://localhost:5201/chatHub

cd ../bar_scene_ws_server
dotnet run         # хаб на /chatHub, CORS разрешает http://localhost:3000
```

## Ограничения

- **Нет авторизации и приватности**: любой, кто знает адрес, попадает в комнату; хаб открыт всем подключившимся и не различает комнаты — изоляция обеспечивается только клиентом.
- **Голос требует защищённого контекста**: `localhost` работает, но при открытии по IP с других устройств нужен HTTPS, иначе браузер не даст доступ к микрофону.
- **Нужен доступ к микрофону и WebGL** на клиенте.
- **STUN без TURN**: используется публичный STUN для установления соединения. При сложном NAT у обоих участников голос может не заработать.
